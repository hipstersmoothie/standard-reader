## Becoming Standard Writer

- [x] **Ported onto current main as `apps/standard-writer`** — the Standard Newsletter app,
      renamed and rebased a month forward. Product strings, cookie and storage keys, log
      prefixes and script filters all say Writer now; the `app.standard-newsletter.*` **lexicon
      NSIDs deliberately do not**, because records already exist in people's repos under them.
- [x] **Publications, not newsletters** — the sidebar and `loadPublicationsFromDb` list every
      publication the account owns (a `leftJoin`, not an `innerJoin`), with
      `newsletterConnected` saying which are mailed. A newsletter is a feature you switch on,
      not the price of appearing at all.
- [x] **Shared packages** — `@standard-reader/db` (one schema, one database, migrations still
      generated by the reader), `@standard-reader/publication-theme` (one palette derivation),
      `@standard-reader/site-config` (one set of normalizers for the site record).
- [x] **TanStack pinned workspace-wide** — the two apps resolved different router/start versions
      and the newer one broke against the pinned `router-core`. Both now build on one toolchain.

## Sites

- [x] **Public routes** `/site/u/$did` and `/site/p/$did/$rkey`, served here rather than by the
      reader, over lean public queries — no read state, no recommend attribution, no comment
      counts, none of which a site needs.
- [x] **Four styles** (Broadsheet, Journal, Gallery, Marquee) over one `SiteViewProps` shape.
- [x] **URL paging** (`?offset=`) so every page of an archive has an address.
- [x] **`/sites` editor** — style picker with live preview, tagline, masthead links, colors,
      colophon toggle, save and reset. Writes `app.standard-reader.site` to the author's repo and
      writes through to the mirror.
- [ ] **Chrome-free article reading** — a post opened from a site still lands on the reader's
      `/a/$did/$rkey` with the app's chrome around it, which breaks the illusion at exactly the
      moment someone starts reading. The reader's `ArticleView` is tangled with its shell
      providers, so a site-side article route needs the renderer extracted first.
- [ ] **OG cards per style** — a shared site link currently gets no image at all now that it no
      longer borrows the reader's OG route. Worth a card that looks like the chosen style.
- [ ] **Fonts on author sites** — publication sites inherit `publicationTheme` fonts through the
      token themes; an author site has no font record of its own. A `fonts` slot on
      `app.standard-reader.site` would close the gap.
- [ ] **Pinned selected work** — Marquee leads with the three most recent posts. Letting an owner
      pin which three is the obvious next control, and the record has room for it.

## Pro & custom domains

- [x] **Entitlement** — `user.pro_since`, read through `isPro` / `requirePro` so the gated set is
      greppable. Set by hand; no billing yet.
- [x] **Domain config** — validated hostname, unique across sites (partial unique index), stored
      only in the mirror and never in the author's repo, and inert until verified.
- [ ] **DNS verification** — nothing sets `custom_domain_verified_at` yet, so a saved domain
      routes nowhere. Needs a CNAME check and a re-check schedule.
- [ ] **Host routing** — `resolveCustomDomain` is written and unused. A request arriving on a
      custom host has to resolve to a subject and render the site route; that is server/proxy
      configuration as much as app code.
- [ ] **Certificates** — whatever issues TLS for customer domains. Blocks the above.
- [ ] **Billing** — a provider, checkout, webhooks, and a place to see what you are paying for.
      Only the code that _sets_ `pro_since` should change.

## Housekeeping

- [x] **Deployment** — `railway.writer.json` is the writer's own Railway service
      (`pnpm writer:build` / `pnpm writer:start`, healthcheck `/api/auth/atproto/metadata.json`,
      deliberately no `preDeployCommand` so it never races the reader on migrations). CI builds
      it, so a broken writer build fails the PR rather than only its preview deploy. Preview
      environments need `DATABASE_URL` (the PR's Neon branch), `ATPROTO_PRIVATE_KEY_JWK` (a
      preview domain is https, so the OAuth client is confidential — without it the healthcheck
      itself 500s), and the two cross-app URLs as Railway service references. See "Preview
      deploys" in the root `CLAUDE.md`.
- [ ] **Preview URL wiring is manual** — `VITE_READER_URL` / `VITE_WRITER_URL` are set per Railway
      environment, and being `VITE_`-prefixed they bake at build time. Unset, each app falls back
      to its production host, so a preview quietly links into prod. Resolving the sibling origin
      at runtime instead would remove the footgun and the redeploy-to-change-it rule.
- [ ] **Tests for the site path** — the four styles and the site queries have no tests of their
      own; `@standard-reader/site-config` covers the normalizers and nothing covers rendering.
